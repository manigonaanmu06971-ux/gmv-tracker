使用说明

从 Excel 版沿用的录入规则，加上本次新增的直播时间相关操作。

1每天怎么用

  1. 首次使用：打开「每日明细」，把顶部起始日期设成你要开始记录的第一天（默认 2026-08-01），日期列自动按天顺延 366 天。
  2. 把目标 ROI 设成自己的实际考核标准（默认 2.50）。
  3. 每天开播前后，在当天那一行点直播开始和直播结束，用弹出的时间选择器点选时刻，不用打字。
  4. 收播后填两个数：GMV 和 ROI。消耗、时长、环比、达标状态、月度汇总、看板全部自动刷新。
  5. 没开播的日子：开始 / 结束时间留空即可，时长记 0，不影响任何平均值。
  6. 改完不用点保存，输入的瞬间就写进浏览器本地存储，刷新页面不丢。

2颜色与字段约定

浅黄底 = 手动填写
直播开始 / 结束、GMV、ROI、备注、起始日期、目标 ROI —— 只改这些。
浅灰底 = 自动计算
星期、直播时长、消耗、GMV 环比、达标状态 —— 只读，不可覆盖。
绿色「达标」
当日 ROI ≥ 目标 ROI。
橙色「待提升」
当日 ROI < 目标 ROI。
  • 日期列左侧有蓝色竖条：这一天已录入 GMV。
  • 日期文字橙色：周六 / 周日。整行米黄底：今天。

3计算公式

消耗 = GMV ÷ ROI本表核心：填 GMV 和 ROI，反推当日消耗
综合 ROI = 累计 GMV ÷ 累计消耗加权口径，不等于每日 ROI 的算术平均
GMV 环比 = 当日 GMV ÷ 前一日 GMV − 1第一天或前一日无数据显示「—」
直播时长 = 结束时间 − 开始时间跨天自动按次日算，如 22:00 → 02:00 = 4.0 小时
月直播时长 = 当月各日时长之和日均直播时长 = 月时长 ÷ 当月有直播的天数
ROI 达标率 = 达标天数 ÷ 已录入天数已录入天数 = 有 GMV 数据的天数

4直播时间怎么填

  • 点开始 / 结束格子，浏览器会弹出原生时间选择器，点选小时和分钟即可；也可以直接键盘输入 20:30。
  • 跨天场次：结束时间早于开始时间时自动按次日计算。例：开始 22:00、结束 02:00 → 时长 4.0 小时。
  • 时长按小时保留 1 位小数：3 小时 30 分 = 3.5；2 小时 45 分 = 2.8（四舍五入）。
  • 只填了开始、没填结束（或反之），时长记 0，请两个都填完整。
  • 开始与结束填成同一时刻时长记 0，如果真的播满 24 小时，请拆成两行记录。
  • 时长归属：一场跨天直播的全部时长，都算在开播那一天所在的月份里。

5看板怎么看

  • 综合 ROI 是加权口径（累计 GMV ÷ 累计消耗），和「每天 ROI 求平均」不是一回事，考核以这个为准。
  • 月度汇总表的直播时长列做了高亮，可以横向对比各月投入的播出时间。
  • 双轴图把时长（柱）和 GMV / 消耗（折线）叠在一起，用来看「多播的月份 GMV 是否同步涨」；如果时长涨、GMV 没涨，说明单位时长产出在下滑。
  • 月度 ROI 折线上的橙色虚线就是目标 ROI，线以上的月份是达标月。
  • 把鼠标移到图表上会显示当月的具体数值。

6数据备份与迁移

  • 导出数据：把全部记录存成 JSON 文件，建议每周备份一次。
  • 导入数据：选择之前导出的 JSON 覆盖当前数据（会先二次确认）。换电脑、换浏览器就靠这个。
  • 清空数据：连续两次确认后清空全部记录并恢复默认参数，不可撤销。
  • 数据只存在当前这台电脑的这个浏览器里，不上传服务器；换浏览器、用无痕窗口、清理浏览数据都会导致看不到记录。

7注意事项

  • ROI 留空或填 0 时，消耗显示为空 —— 这是保护逻辑，不是报错，不会出现 NaN / ∞。
  • 明细表固定生成 366 天（整年容量）。改了起始日期，超出新范围的旧数据仍保留在存储里，但不参与看板统计；把起始日期改回去就能重新看到。
  • 月度汇总覆盖明细表全部日期范围，整年通常是 13 行（最后一行只含收尾的一两天），合计行始终与看板卡片对得上。
  • GMV 请填元为单位的原始数字，不要带逗号、不要填「12.5万」。
  • 筛选和排序只影响显示，不改数据；GMV 环比始终按真实前一日计算，与当前排序无关。
